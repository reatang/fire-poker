# 数据目录

## 目标

沿用 agent 类软件的通用习惯，把所有数据统一放在用户家目录下的 `~/.fire-poker`，三个平台路径一致，便于文档说明、手动编辑、备份和同步。普通用户无需记住路径，通过设置页的「数据管理」查看。

## 目录约定

| 路径 | 内容 | 能否删除 |
| --- | --- | --- |
| `~/.fire-poker/config.json` | 应用设置、扩展列表 | 删除后恢复默认设置 |
| `~/.fire-poker/data.db` | 供应商、会话、消息、记忆等 | 删除即丢失全部对话 |
| `~/.fire-poker/skills/` | 用户 Skills | 删除即丢失自定义 Skills |
| `~/.fire-poker/plugins/` | MCP、插件、CLI 工具及其数据 | 删除即丢失已安装扩展 |
| `~/.fire-poker/logs/` | 按天切分的运行日志，保留 14 天 | 可随时删除 |
| `~/.fire-poker/cache/` | Node 运行时、Windows WebView2 数据 | 可随时删除，Node 运行时会提示重新下载 |

不在数据目录内、由系统决定的位置：

- macOS WebView 数据：`~/Library/WebKit/com.reatang.fire-poker`、`~/Library/Caches/com.reatang.fire-poker`
- 附件临时文件：系统临时目录下的 `fire-poker/`，启动时清理

## 解析规则

1. 环境变量 `FIRE_POKER_DATA_DIR`（兼容 `LEMONTEA_DATA_DIR`），Windows 便携版依赖它
2. 旧版定位文件 `~/.fire-poker/data_dir.json`（仅兼容读取）
3. 默认 `~/.fire-poker`；不存在而 `~/.lemontea` 存在时沿用旧目录

## 改动

1. 开发版隔离：未带 `production` 构建标签时使用 `~/.fire-poker-dev`，`Info.dev.plist` 使用 `com.reatang.fire-poker.dev`，避免 `wails3 dev` 改动真实数据
2. 测试隔离：测试进程未设置 `FIRE_POKER_DATA_DIR` 时，`GetDataDir` 返回进程级临时目录，不再读写真实数据
3. 缓存归位：Node 运行时由 `runtime/node` 移至 `cache/runtime/node`，Windows WebView2 由 `webview2` 移至 `cache/webview2`；启动时一次性改名迁移，并改写 `state.json` 中的绝对路径
4. 日志：标准库 `log` 同时写入 stderr 与 `logs/YYYY-MM-DD.log`，启动时清理 14 天前的日志
5. 单实例：启用 Wails `SingleInstance`，再次启动时聚焦已有主窗口
6. 设置页新增「数据管理」一级菜单，只读列出上述目录、是否存在，并提供复制路径、在文件管理器中打开
7. 下线「通用 → 文件」中不可用的自定义数据目录入口及其后端 `ApplyFileSettings`

## 验收标准

1. 正式版数据仍在 `~/.fire-poker`，老用户升级后对话、扩展、Node 运行时均可用，无需重新下载
2. 开发版、测试不再改动 `~/.fire-poker`
3. 设置 → 数据管理可看到全部目录，路径只读，能复制、能打开
4. 重复启动应用只保留一个实例
5. 日志文件出现在 `~/.fire-poker/logs/`
